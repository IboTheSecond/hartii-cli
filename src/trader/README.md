# Local holder trader adapter (BETA)

`hartii trader paper --demo --once --json` is an offline, transaction-keyless proof. It uses explicitly labeled empty demo market data and cannot qualify or enable Live. The packed CLI includes the engine through the existing vendor builder.

Normal setup records separate public owner/trading addresses and four absolute QUAI budgets. `--wallet <name>` selects an existing encrypted dedicated wallet by metadata; `--create-wallet` explicitly creates one. Without either option, Observe/Paper require no transaction key. A profile is stored below `HARTII_HOME/trader/<profile>`; the default profile is `default`. Protected atomic writes reject linked storage paths. File mode requests alone do not certify Windows ACLs.

```text
hartii trader init --owner <address> --trading-address <address> --capital 100 --max-per-tx 10 --max-per-day 30 --max-fee 1
hartii trader init --pair
hartii trader paper --once
hartii trader run --observe --once
hartii trader watch --once --json
hartii trader status --json
hartii trader pause
hartii trader export --mode all --out trader-history.jsonl
```

Pair before the first cycle. Pairing codes use hidden input; Ed25519 device credentials are persisted in an AES-GCM/scrypt envelope before redeeming the one-use code. The owner then confirms the displayed device fingerprint in the dashboard. Heartbeat/event requests sign the exact canonical body hash, path, runner, timestamp and fresh nonce. A serialized 15-second telemetry pump reports actual phases during a cycle; event delivery failure does not prevent heartbeat or remote pause checks. A remote pause becomes a durable local latch. A confirmed receipt remains necessary for any transaction already broadcast.

To select a paid model, provide `--provider openai|anthropic --model <explicit-model> --pricing-file <file>` during initialization. `--model-key-env <NAME>` records only an environment variable name; otherwise a hidden prompt stores the model key in the encrypted credential envelope. The pricing file must include all four decimal integer microusd-per-million rates (`inputMicrousdPerMillion`, `outputMicrousdPerMillion`, `cacheReadMicrousdPerMillion`, `cacheWriteMicrousdPerMillion`) and positive integer `maxInputTokens`/`maxOutputTokens`. The shared engine budget caps estimated model cost at 100000 microusd/cycle and 1000000/day. No model/provider fallback exists.

For a paired profile, `hartii trader arm --wallet <dedicated-name>` first displays and proposes its explicit budgets. Only the dedicated trading wallet unlocks locally to prove ownership by signing the canonical policy message. Review and sign the policy with the ownership wallet in the dashboard, then repeat the command: it verifies the exact saved proposal, current identity/budgets, compiled release and owner signature before requiring local typed `ARM` and claiming exclusive authority. The browser signature does not arm the runner. `--yes` cannot bypass local confirmation. `hartii trader arm --policy-file <file>` also accepts a reviewed `{policy,signature}` envelope, submits the same trading proof for a paired profile, and still requires local `ARM`.

Policy expiry is at most 24 hours. Policy replacement alone never resumes a runner. An ordinary pause needs a fresh owner-signed policy issued after that pause, a new hosted claim, local typed `ARM`, and a durable acknowledgement of the exact pause identity. A newer pause always remains active. This does not clear a financial loss, unresolved accounting, or pending-transaction latch. If setup used only a public trading address, import that dedicated trading key into the ordinary encrypted wallet store and select it with `--wallet <name>`; its public address must match before a Live cycle starts. `trader reconcile` uses public receipt evidence, including after policy expiry. A paired profile unlocks its local device credential to reconcile hosted authority; it does not unlock the transaction wallet or call a model provider.

## Trusted integration seams

- `readers.js`: `readTraderStatus(opts,deps)`, `readTraderLimits(opts,deps)`, `readTraderActivity(opts,deps)`, and `createTraderReader(opts,deps)`. The reader has only status/limits/activity/pause; caller input cannot override its configured home/profile. Activity/report export is a bounded sanitized view, while the complete financial journal remains local.
- `runtime.js`: paired runners use `services.js` for signed policy, qualification and authority APIs and public membership reads by default. `deps.traderServices` remains an injected test/integration seam. The compiled `TRADER_RELEASE_ID` is `holder-trader-0.3.0-rc.1`; it cannot be overridden by argv/environment or adopted from a server's newer release. Root must pin the final reviewed source/package digests before observations or signoff. A behavioral change after qualification starts requires a new release identifier and observation window. With missing/stale/unqualified evidence, Live remains blocked. Runtime tests never activate a real wallet, provider bill, or funded transaction.
- `market.js`: public Hartii directory/candles plus read-only chain calls verify factory/token/curve and direct pair binding, launch-block snipe completion, contiguous closed one-minute history, fresh quotes, gas, impact and round-trip costs. Managed token balances are checked; discovered excess units are quarantined. Unknown marks prevent new risk.
- **Future exit reserve:** a new wallet cannot usually estimate a sell before it owns/approves the token. The default reserves the policy's entire `maxFeeWei` for that future transaction, plus an actual approval estimate or another complete fee ceiling if approval cannot be estimated. This is a conservative monetary reserve with `policy-fee-ceiling` provenance, never a claimed gas estimate. Paper may also use that ceiling for an unfunded simulated entry; Live entry and Live sell after confirmed approval always require a complete actual estimate and must fit the fee ceiling. Full conservative costs enter the round-trip guard, so a small capital budget may correctly Hold. Optional `deps.estimateFutureExit({provider,route,from,tokenUnits,transaction,approvalTransaction,gasPrice})` can instead return reviewed `{basis:'verified-generation-bound'|'rpc-state-override',evidence:string,checkedAt,gasWei:string,approvalGasWei?:string}`. Quote fields `gasBasis`, `exitGasBasis`, `approvalGasBasis`, `gasEvidence`, and `exitGasEvidence` identify the provenance.
- `deps.readFunding({provider,wallet,now,positions})` may return independently verified, uniquely identified deposit/withdrawal flows for the engine. There is no guessed balance-difference funding classification: absent verified flow evidence, an unexpected cash change blocks new risk. Reconciliation never releases unknown local spend authority on the basis of a balance alone.
- `executor.js`: `createLiveExecutor(opts,deps)` reuses the existing buy/sell/swap commands and their spend/nonce/signature checks. A trusted `io.onSignedTransaction` callback waits after canonical byte validation but before final chain/nonce/expiry checks. `prepare` signs only; the engine persists its hash before `broadcast` releases the permit. `discard` returns exact-hash cancellation proof only after the native command has completed without broadcast. A missing allowance becomes an explicit engine approval intent for the exact managed token, verified spender, and full managed units. It uses the same native write pipeline, its own durable hash, and an exact `Approval` event with gas-only accounting. The next cycle reads allowance and refreshes the sell. No prepared continuation can send both approval and sell. Simulated approvals are honored only in Paper; Live always reads actual allowance.

Unknown transaction hashes stay pending in both the engine journal and CLI spending ledger. Reconciliation checks the transaction/receipt identities, final status, actual gas and bound trade events, then settles each journal once. A verified local receipt is kept when the hosted service's 20-block confirmation gate is still pending. A separate protected hosted-settlement queue persists the public hash, blocks new signing and retries on subsequent gates or `trader reconcile`. Journal locks do not expire automatically after a crash.

The local activity cache keeps 1000 public events and read tools return at most 100. A stopped-writer export streams every validated financial journal record to a protected JSONL artifact with explicit mode boundaries and integrity hashes. Invalid, partial or unsafe records fail before publishing the artifact. A separate fsynced outbox retains the entire unsent sequence and replays it in bounded requests after restart. Missing outbox appends are reconstructed from the durable engine journal by event identity. Financial journals and outboxes bind the compiled release; historical decisions are never relabeled for a newer release. Read-only status/export and explicit public recovery remain available when an older release's history blocks new signing or observation.
